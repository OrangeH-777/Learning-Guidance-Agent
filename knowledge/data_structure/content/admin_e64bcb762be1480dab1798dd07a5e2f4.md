# 线性表：顺序存储与链接存储

线性表是有顺序的元素序列。数组用连续位置存储，按合法下标访问为 O(1)；在中间插入或删除通常需要移动后续元素，最坏为 O(n)。动态数组扩容需要复制，不能把每一次尾部插入都说成最坏 O(1)，常见倍增策略下它是摊还 O(1)。

链表通过结点间链接表达顺序，按位置查找通常需要遍历。单链表在已知前驱时可用 O(1) 时间插入或删除相邻结点；寻找前驱的成本必须另计。双链表用额外前驱链接换取操作便利，仍不具备数组式随机访问。讨论空表、头尾结点和下标越界时应先明确约定。

## 示例教材：顺序表插入

本节为项目原创演示教材，用于验证资料导入、切块、检索和引用，不代表已经通过课程负责人审核。

设顺序表为 [12, 25, 37, 49]，下标从0开始，在下标2处插入30。先将49向右移动，再将37向右移动，最后写入30，得到 [12, 25, 30, 37, 49]。移动必须从尾部向前，否则会覆盖尚未搬移的元素。插入位置允许从0到当前元素个数，访问已有元素的位置则只能从0到元素个数减1。

## 示例教材：单链表插入

已有 A → B → C，已知结点A，要在A后插入X。先令 X.next 指向原来的 A.next，再令 A.next 指向X，得到 A → X → B → C。如果先修改 A.next 再用它寻找原后继，会丢失原来的链接。这里的O(1)只指修改链接，不包括按序号查找A的过程。

## 自测与解析

问题：系统需要频繁按下标读取第100个元素，偶尔在末尾追加，数组和普通单链表哪个更合适？

解析：通常优先考虑动态数组，因为下标读取为O(1)，常见倍增扩容下追加为摊还O(1)。普通单链表需要从表头遍历；是否合适仍取决于连续内存需求和实际数据规模。不要把动态数组每一次追加都说成最坏O(1)。
